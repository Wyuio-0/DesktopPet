# 同步数据的合并与覆盖

`POST /api/sync/push` 的 `mode` 支持 `merge`（默认）和 `replace`。PC、Android 和 iOS 按下面的规则处理课表、考试和便签。

| 请求内容 | merge | replace |
| --- | --- | --- |
| 没有某个类别字段 | 该类别不变 | 该类别不变 |
| 没有 `schedule.courses`，只提供学期设置 | 课程不变，应用提供的设置 | 课程不变，应用提供的设置 |
| 某个列表是 `[]` | 不删除本地记录 | 清空该列表并持久化 |
| 列表有记录 | 与本地合并 | 仅保留收到的记录 |
| 列表为 `null`、非数组、关键字段无法解析、ID 无效或重复、模式未知 | 返回加密 400，不应用该请求 | 返回加密 400，不应用该请求 |

集合字段为 `schedule.courses`、`exams`、`notes`。未提供的字段和显式空列表含义不同；不能通过把 `null` 转换成 `[]` 来处理错误输入。

PC 将考试保存为任务，覆盖 `exams` 只替换考试任务，不删除本地作业。Android 和 PC 不再在加载一个有效的空便签文件时重新创建欢迎便签。PC 空编辑器不会仅因打开就生成便签，用户开始输入后才创建新便签。同步也会更新已经打开的 PC 便签管理器，取消旧正文的延迟保存，避免被覆盖的内容重新出现。

Android 打开的便签编辑页若发现原记录已被同步修改或删除，会退出该旧版本的编辑。延迟保存还会校验打开时的记录版本，防止同 ID 的旧正文覆盖新内容；便签操作与同步替换使用同一对象锁。

## 合并规则

- 课程与考试优先按稳定 ID 更新。为兼容旧版本重新导入的数据，课程还按完整上课安排识别，考试按名称与时间识别。合并不传播删除。
- 便签按 ID 合并，仅在远端 `updated_at` 更新时采用远端内容；时间相同保留接收端内容。当前时间精度为分钟，尚不提供冲突副本或版本向量。
- 覆盖不按更新时间选择内容，以本次提供的列表为准；不同 ID 的考试即使名称与时间相同，也保留为不同记录。
- PC 同步请求的打包与应用串行执行，避免另一个同步请求读到替换到一半的类别。便签同步与编辑器延迟保存共用锁。

三端会先解析本次提供的类别，再更改集合。该检查防止格式错误造成部分清空；它不构成磁盘故障或断电时的跨文件事务，也没有增加自动备份功能。

## 界面行为

PC 和 Android 的“双向合并”先拉取并合并，拉取失败立即停止；拉取成功后以 `merge` 推送，不再借合并按钮执行远端覆盖。普通客户端推送默认也是 `merge`。iOS 的现有推送继续使用合并。

PC 与 Android 的显式覆盖按钮会说明将删除目标独有内容，空列表会清空对应类别，并要求确认。PC 拉取按钮的文字改为“拉取并合并”，与实际行为一致。

## 验证范围

PC 回归覆盖：空覆盖及重载、只覆盖部分列表、保留作业、覆盖旧便签、合并保留新便签、无效输入在写入前拒绝、并发请求不能读到部分替换、编辑器旧延迟保存不能复活删除内容、双向同步在拉取失败后不推送。

Android 独立 instrumentation 新增同类用例，并通过真实加密 HTTP 检查 PC → Android、Android → PC 的覆盖清空及无效请求 400。USB 通道不等同于 Wi-Fi 实测；iOS 由 CI 原生构建检查，尚无 iOS 真机验收。
